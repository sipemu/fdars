<objective>
Stand up the external `benchmarks/` harness as a production-quality end-to-end TRACER for ONE operation (FPCA): a seeded single-source generator produces a matched CSV; the Python, R, and Rust runners each consume that identical CSV and time FPCA; the criterion collector reads fdars FPCA timing from the existing `estimates.json`; the numeric-agreement gate sign-aligns and verifies FPCA loadings BEFORE any timing is recorded; and `env.json` captures pinned-thread + version + BLAS + CPU metadata. This is the thinnest full path through every layer the phase touches — proven working before Plans 02/03 expand to the full op set.

Purpose: De-risk the harness architecture (generator -> 3 runners -> collect -> gate -> env capture) on one clean, deterministic op (FPCA) before building out. If the architecture is wrong, we learn it after one commit, not ten.
Output: All harness scripts (FPCA-only bodies), pinned `requirements.lock` + `renv.lock`, a working `run_all.py --op fpca` path, and `env.json`.
</objective>

| T-112-03 | Information disclosure | env.json contents | low | accept | env.json contains only version/BLAS/CPU/thread metadata; no secrets. Committed as reproduction evidence. |
