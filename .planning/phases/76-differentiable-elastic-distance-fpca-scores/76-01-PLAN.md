<objective>
Deliver DIF-02: two fully-differentiable, generic-over-`Scalar` elastic-distance operations that live ALONGSIDE their existing f64 counterparts:

1. `soft_dtw_distance_generic<S: Scalar>(x, y, gamma) -> S` — the differentiable pilot. Instantiated at `Dual` it yields exact forward-mode gradients (validated against the crate's own hand-written soft-DTW gradient oracle AND central FD); instantiated at `f64` it reproduces the existing `soft_dtw_distance` bit-identically.
2. `amplitude_distance_at_warp_generic<S: Scalar>(...)` — the fixed-warping SRSF amplitude distance (per D-discretion, the achievable differentiable elastic-distance deliverable; the warp-SEARCHED `elastic_distance` is OUT OF SCOPE because its DP argmin is discrete/non-differentiable).

Purpose: gradients of an elastic distance w.r.t. a curve's sample values now flow through, enabling gradient-based optimization of curve shape — while every existing f64 public signature and behavior stays byte-for-byte unchanged (protects R + WASM bindings + 28 examples).

Output: generic functions + inline tests in `metric/soft_dtw.rs` and a new `alignment/differentiable.rs`, all gates green.
</objective>

<deferred_scope>
## Explicitly OUT OF SCOPE (document in code + SUMMARY)

- **Warp-SEARCHED `elastic_distance` / `amplitude_distance` / `phase_distance_pair`** — these route through `dp_alignment_core_banded`, a discrete argmin over DP path cells. The optimal-path *indices* are integers (piecewise-constant in the inputs), so forward-mode `Dual` would propagate a ZERO gradient through the warping — misleading, not useful. DIF-02's differentiable elastic-distance deliverable is therefore the FIXED-warping formulation (`amplitude_distance_at_warp_generic`), where the pre-computed warping is a `&[f64]` constant and only the second curve's values are differentiated. State this in the module doc comment of `alignment/differentiable.rs`.
- Closed-curve / n-D / banded generic variants — deferred (DIF-F2 / other phases).
- Genericizing `srsf_single` / `srsf_transform` / `deriv_1d` (they take `&FdMatrix` = `Vec<f64>`) — use the generic central-difference SRSF instead.
</deferred_scope>
