    - Test: a criterion record with RSD>=5 OR CI-width>=5 is excluded from target selection and appears in the noise-excluded set.
    - Test: compute_leverage(fdars_ns, min_other_ns) = fdars_ns × max(1.0, fdars_ns/min_other_ns); when fdars is fastest (fdars_ns < min_other_ns) leverage == fdars_ns × 1.0 (no speedup bonus).
    - Test: ranking is deterministic — the same comparison.csv rows produce byte-identical ordering across two runs (stable sort by descending leverage_score).
    - Test: a row with min_other_ns<=0 or fdars_ns<=0 falls back to fdars_ns without dividing by zero.
    - Test: the elastic op is present in the ranked output sourced from the noise-stable elastic cell (pairwise/self-distance), NOT from a noise-excluded Karcher-mean cell.
  </behavior>
  <action>
    Create rank_hotspots.py that reads comparison.csv (pandas) and computes: (1) a noise_gate filter — a rust/criterion row PASSES only if rsd_pct<5.0 AND ci_width_pct<5.0 (per the auto-accepted measurement-noise gating decision); rows failing are collected into a "noise-excluded" list and NOT used for target selection; python/r rows (noise_gate='NA') are carried for the cross-language leverage denominator but are not themselves ranked targets. (2) leverage_score = mean_fdars_ns × max(1.0, mean_fdars_ns / min_other_ns) where min_other_ns = min of the python/r_svd mean_ns for the same op/size (the RESEARCH formula; the fdars=fastest case yields absolute-time-only). Guard division: if min_other_ns<=0 or fdars_ns<=0, leverage_score=fdars_ns. (3) A deterministic ranking via sorted(..., key=lambda r: -r["leverage_score"]) (stable sort; Don't-Hand-Roll). For the elastic anchor use the noise-stable elastic cell (elastic_align_pair / elastic_self_distance_matrix) NOT the noisy Karcher-mean cell (Pitfall 3) — the ranking must CONFIRM the elastic anchor from clean numbers. Exclude fpca_native_r from ranking (ecosystem-realistic only, not numerically matched). Write test_rank_hotspots.py covering the <behavior> cases (including the two Nyquist-mapped tests: test_noise_gate_flags_high_rsd and test_leverage_score_deterministic per 113-VALIDATION). TDD: RED then GREEN. Do not embed literal gate-message strings a test negative-greps for inside comments.
