## Design
One padded `(n+1)×(m+1)` lattice core (`Lattice::fill` over `DtwWindow::row_bounds`) + per-distance
cell closures and border inits; generic `Recipe` drives distance / cost matrix / path / pairwise;
a `macro_rules!` generates the four documented public fns per distance. aeon's
`compute_min_return_path` (np.argmin first-min) and `compute_lcss_return_path` ported.
Max cognitive complexity in new code 15 (pmat); aeon Sakoe port split into helpers.

## Deviations from aeon (documented in module docs)
- No admissible alignment under a window → `ComputationFailed` (aeon returns inf).
- aeon's `lcss_alignment_path` loops forever when its traceback hits an out-of-window cell; we take
  the non-match step (5 such cases have no aeon path golden; tested for termination/validity).
- aeon's `erp_alignment_path` ignores `itakura_max_slope`; we honour it (4 cases without path golden).
- aeon's equal-length `ddtw/wddtw_pairwise_distance` sizes the window for raw length n, not the
  n−2 derivative, contradicting its own pointwise distance; we follow the pointwise definition
  (windowed pairwise goldens for these two built from aeon pointwise calls).
- Univariate only (aeon multivariate arrays not supported; MSM `independent` kept since it changes
  the univariate cost).
