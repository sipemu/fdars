## Conventions (documented on `CurveShapeMetric` / `ab_transform`)
- Metric `∫ a²⟨D_s h,N⟩⟨D_s k,N⟩ + b²⟨D_s h,T⟩⟨D_s k,T⟩ ds`; `F = 2b|c'|^{1/2} e^{iλθ}`, λ = a/(2b), geomstats 2.8.0 `FTransform` k = 0 branch (θ(0) = atan2 ∈ (−π, π], continuous lift by signed increments; we use atan2(cross, dot) instead of geomstats' sign(det)·arccos).
- **SRVF is a = 1, b = 1/2** (geomstats docstring "When a=1, and b=1/2, it is equivalent to the SRV metric"); the issue text's "a=1/2, b=1" is the wrong way round (that pair is λ = 1/4).
- Reparametrisation action derived: F(c∘γ) = (F(c)∘γ)·√γ' (direction factor invariant under γ' > 0) → shared DP engine unchanged.
- Rotation: rotating c by φ multiplies F by e^{iλφ} (modulo branch factor e^{2πiλk}); full SO(2) Procrustes in F-space is the exact quotient over rotations and branches; reported curve rotation Rot(ψ/λ) (with reflection S mapped to S). `rotation = false`: plain L² of k=0 branches (= geomstats `ElasticMetric.dist`).
- Scale: ‖F‖² = 4b²·length. `scale = false` → ‖F1 − F2*‖ (geomstats pull-back distance); `scale = true` → great-circle angle on the unit sphere (radius-free, like SRVF); g^{a,b} geodesic length on unit-length curves = 2b·θ. Reconstructed curves are rescaled to unit length.
- Inverse: left inverse for λ ≤ 1, right inverse for λ ≥ 1 (same as geomstats, whose inverse "only works if a/2b ≤ 1").
- Quadrature: central differences + trapezoid on m nodes (as SRVF), vs geomstats forward differences + left Riemann sum on m−1 segments; both second order, ≤ 9e-7 relative gap at m = 2001.

## Validation (`curve_shape/ab_tests.rs`, 20 tests)
- geomstats 2.8.0 goldens (script `golden_geomstats_ab.py`, output `golden_geomstats_ab.out`): pointwise F for 5 (a,b) pairs (λ = 1, 0.25, 0.5, 1.5, 2) on a spiral whose lift leaves (−π, π] (1e-12); inverse left/right-inverse behaviour incl. the λ=2 case where geomstats' inverse also fails; `ElasticMetric.dist` at k = 9 reproduced exactly with geomstats' discretisation (1e-12) and at k = 2001 via `curve_shape_distance` (rel 1e-5).
- Closed forms: bending-only (segment vs arc, d² = 8b²(1 − sin λκ/λκ)) and stretching-only (d = 2b‖1 − √(1+t)‖) distances, rel 1e-5.
- SRVF special case: `ab_transform(·,1,1/2) = curve_srvf` (1e-13); (ka,kb) scales F by k; Elastic{1,1/2} reproduces SRVF alignment (distance, rotation, γ, aligned curve; 4 configs) and Karcher mean to 1e-8; default metric = Srvf (existing 39 curve_shape SRVF/golden tests unchanged and passing → bit-identity).
- Invariants: reparam action F(c∘γ) = (F∘γ)√γ' with clean O(h²) convergence (ratio ≈ 15.5 from m=501→2001); rotation invariance (1e-9) + recovered rotation + aligned curve; reparam invariance (warped copy at DP floor, < 1/3 of rigid distance); d_reparam ≤ d_noreparam (exact); symmetry + triangle inequality on random 6-curve sets for 4 rotation/scale combos (1e-10); distance matrix = pairwise; inverse recovers curve (O(h²)); Karcher mean of rotated/scaled/translated/warped copies recovers the template (< 0.05) at unit length; PCA/median/box plot run and reconstruct through the F inverse; validation errors.

## Deviations / notes
- geomstats' `DynamicProgrammingAligner` is SRV-only (hard-codes `SRVTransform`), so with-reparam (a,b) distances are validated by invariants, not goldens. geomstats' `IterativeHorizontalGeodesicAligner` (metric-generic, approximate path-straightening) was not used as a reference.
- Observed (pre-existing, not changed here): the shared DP engine has a grid-independent residual floor (~0.015–0.02 SRVF distance, warp error ~5e-3–1e-2 for the test warp at m = 51…401); under the (a,b) metric it grows with λ (~0.04 at λ = 2). Tolerances in reparam tests are set relative to that documented floor (the SRVF tests use 0.03).
- Rotation=false keeps the k = 0 branch distance (geomstats-compatible) rather than minimising over branches.
