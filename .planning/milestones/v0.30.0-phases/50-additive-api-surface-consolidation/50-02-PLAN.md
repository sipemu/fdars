<objective>
Item #2 — seedable fanova. Add `pub fn fanova_seeded(data, groups, n_perm, seed)` and turn the existing
`fanova(data, groups, n_perm)` into a `#[deprecated]` shim delegating with the legacy fixed seed 42.
This is the phase's first introduction of `#[deprecated]`, so it also establishes the deprecation-hygiene
discipline under `clippy --all-targets -D warnings` that plan 50-03 reuses: the crate's own callers of a
deprecated fn become hard errors, so each internal caller is either migrated to the new form (examples +
integration tests) or silenced with `#[allow(deprecated)]` (behavior-pinning unit tests + the golden).

CRITICAL (RESEARCH pitfall #3): fanova does NOT use StdRng — it uses a hand-rolled LCG seeded with a
hardcoded 42 (`let mut rng_state: u64 = 42;` at src/function_on_scalar.rs:839, multiplier
6_364_136_223_846_793_005, increment 1, bit-extract `(rng_state >> 33) as usize % (i+1)`). `fanova_seeded`
MUST keep that exact LCG and change ONLY the seed source (`= seed`). Switching to
`StdRng::seed_from_u64(seed)` would produce a DIFFERENT byte stream → different permutations → different
p-value → the deprecated shim would NOT reproduce the old output. The StdRng migration is a breaking
behavior change deferred to APIB-01; document the deliberate LCG divergence from the sibling seeded fns
(frechet_anova/t_perm_test/f_perm_test use StdRng) in the fanova_seeded doc-comment.

Purpose: close the reproducibility gap (seedable permutation p-values) additively, with the old path
preserved bit-identically. Output: fanova_seeded + deprecated shim + equivalence_phase50.rs golden +
migrated/silenced internal callers, all green under both feature configs, examples, wasm, and -D warnings.
</objective>
