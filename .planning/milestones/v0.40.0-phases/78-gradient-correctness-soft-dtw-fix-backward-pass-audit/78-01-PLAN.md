<objective>
Fix the CORR-01 endpoint-seed defect in `soft_dtw_backward` and prove it with tests that FAIL on the buggy code and PASS after the fix.

The bug: the reverse double-loop in `soft_dtw_backward` (`fdars-core/src/metric/soft_dtw.rs:262-306`) visits the endpoint `(n, m)` first and the unconditional write `e[i][j] = a + b + c;` at line 302 zeroes the manually-set `e[n][m] = 1.0` seed (all three neighbour contributions `a`/`b`/`c` are gated off at the endpoint), which zeroes the entire backward pass and makes `soft_dtw_barycenter` silently descend on a zero gradient. The fix is a single `if i == n && j == m { continue; }` guard, exactly as already prototyped in the `corrected_oracle_gradient` test helper (lines 485-486). The shipped exponent formula is already algebraically correct (`r[i][j] - r[i+1][j] + r[i+1][j]` collapses to `r[i][j]`) — DO NOT change it.

Scope guard: fix ONLY the endpoint-seed defect. Do NOT redesign the barycenter optimizer or touch the caller chain (`soft_dtw_accumulate_gradient`, `soft_dtw_barycenter` need no change — the fix propagates automatically).

Purpose: CORR-01 — the acknowledged soft_dtw zero-gradient bug is corrected, with a regression test proving non-zero gradient AND real barycenter movement, and the three existing barycenter tests tightened so they can no longer pass on an all-zero gradient.
Output: fixed `soft_dtw_backward`, new SC#1 regression tests, tightened existing tests, updated `corrected_oracle_gradient` doc comment.
</objective>
