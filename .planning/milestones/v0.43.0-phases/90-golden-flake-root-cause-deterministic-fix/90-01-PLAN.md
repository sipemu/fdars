<objective>
Root-cause the three known flaky golden tests with committed evidence (FLAKE-01), then apply the evidence-chosen deterministic fix and prove it (FLAKE-02).

The three tests are:
- `golden_co_cluster_parallel` (fdars-core/tests/equivalence_phase48.rs, n_init=4, parallel branch)
- `golden_co_cluster_below_threshold` (fdars-core/tests/equivalence_phase48.rs, n_init=2, sequential branch)
- `svd_sign_fpca_two_matrix_bit_identical` (fdars-core/tests/equivalence_phase49.rs)

FLAKE-01 GATES FLAKE-02: the diagnosis (Wave 1) must be written and committed before the fix (Wave 2) is chosen. The diagnosis must reconcile the historical symptom (MEMORY.md: intermittent failure under full parallel `cargo test`, passing per-binary) against the reproduction (RESEARCH.md: deterministic failure whenever the test binary is compiled without `--features linalg`, because `fdata_to_pc` then routes through the nalgebra SVD backend instead of faer, algorithmically diverging the FPCA rotation). If observed evidence contradicts the cfg-guard hypothesis, the fix must follow the evidence per the CONTEXT.md decision hierarchy (test-side robustness → std-only Mutex only on a proven race → minimal src/ determinism as last resort; tolerance relaxation only where FP nondeterminism is proven).

Purpose: Remove the release-blocking flake with a least-invasive, diagnosis-justified change so the full-suite determinism gate (Phases 92–93) has a green baseline.
Output: A committed `90-DIAGNOSIS.md` artifact and the two test files carrying the evidence-chosen guard, proven by 10 consecutive green full-parallel runs plus per-binary green.

Out of scope (do NOT pull in): suite-wide sweep (Phase 91), CI guardrail (Phase 92), release prep / version bump / CHANGELOG (Phase 93).
